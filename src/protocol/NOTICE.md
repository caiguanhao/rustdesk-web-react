## Local modifications (P1-1)

All additions are marked `P1-1 addition` in `message.ts`; `rendezvous.ts` is
unmodified apart from the provenance header.

- `ClipboardFormat` enum and `Clipboard.format` (field 5), default `Text`.
- `MultiClipboards` and `Message.multi_clipboards` (field 28).
- `LoginRequest.version` (field 11) and `my_platform` (field 13); both stay
  empty unless `advertiseWebClientVersion` is enabled, so v1 bytes are
  unchanged by default.
- `KeyboardMode` enum and `KeyEvent.mode` (field 9), default `Legacy`.
- `VideoFrame.display` (field 14), default `0`.
- `PublicKey.kx_version` (field 3), always sent as `0` to select the v1 key
  exchange scheme; zero is omitted on the wire.

Defaults equal the protobuf zero value and are omitted when encoding, which is
why v1-encoded messages remain byte-identical. Unknown fields are skipped by
the generated decoders.

Tests compare encoding against `tests/fixtures/v1-protobuf.json`, generated
once from the pristine v1 modules (see the fixture's `source` metadata).
